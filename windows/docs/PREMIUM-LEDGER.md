# Premium ledger: Song2Vid for Windows

One row per rule of the desktop-app skill's premium bar (`references/premium-bar.md`, rules 1 to 111 and 41b), as ADR-023 and SPEC section 28 ask. A rule **applies** (its check is named, and its verdict per run is **verified**, **unmet** or **unverified**) or is **N/A** with a one-line reason. Rule wording and check names are the skill's, copied from skills commit `48b054d16de2fbcdcb30487471967dda176b469b` (branch `beta`); `windows/app/PROVENANCE.md` names the same commit.

Status of this file: written by S2V-028 before any screen exists. Every row that applies is "applies, pending": no verdict has been recorded, because nothing has been built or run against it yet. S2V-030 and S2V-031 record verdicts. The N/A rows are the ones SPEC 28 lists as known, "unless the build shows otherwise"; a build that shows otherwise changes the row and says why. The handoff says "passes the automated bar", lists every row not verified, and never says premium (SPEC 28).

Where each check runs (SPEC 28): headless gates (`typecheck`, `test`, `shell:check`, `qa:audit`, `qa:visual`, `fuses:check`, `qa:planted`) on the Mac and on Titan; every check that opens a window (`qa:crash`, `qa:kill`, `shell:evidence`, `measure:focus`, the installed check) on the DeskMini.
