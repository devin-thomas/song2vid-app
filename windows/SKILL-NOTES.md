# Notes on the desktop-app skill, from building Song2Vid for Windows

Started by S2V-028. Two lists, kept current by every later Windows app ticket (S2V-029 to S2V-032): every change to a starter file outside its marked replace-me blocks, with the reason (SPEC 27.1), and anything in the skill that was hard for an outside developer to follow, so it can go back to the skill as feedback (ADR-022).

Source: `devin-thomas/skills`, branch `beta`, folder `beta/desktop-app`, commit `48b054d16de2fbcdcb30487471967dda176b469b` (2026-11-22). The app is `windows/app/`; its `PROVENANCE.md` names the same commit. The git history of `windows/app/` shows the starter as copied (the commit "Copy the desktop-app web-three-systems starter, unchanged", which differs from the skill's folder by one `.gitignore` line, below) and each change after it.

What counts as a "marked block". The starter's README step 5 names the replace-me parts in prose: the screen in `src/App.tsx` and `src/components/StatusBar.tsx`, the job in `src/state/job.ts` and `electron/tool/index.ts`, the contract names in `electron/tool/contract.ts`, the scenarios in `test/scenarios/` and the fixtures in `src/bridge.fake.ts`, the menu in `electron/menu.ts`, and the states, journey scripts, shortcut effects and job fixtures of `qa/audit.ts`, plus `qa/shots.ts`, `qa/lib.ts` (`fill()`), `electron/qa.ts` and `measure/workload.js`. The seam files (`src/bridge.ts`, `docs/BRIDGE.md`, `docs/JOURNEYS.md`, `qa/journeys.json`, `shortcuts.json`, `qa/banned-terms.json`, `docs/TOOL-CONTRACT.md`) are replaced by design (step 4). The list below is everything else, plus each replace-me file already touched, so a later ticket can see the whole set.

## Known red after S2V-028, on purpose

The seam files replace the starter's example before the screens exist. At the commit that holds them: `pnpm shell:check` and `pnpm test` pass; `pnpm build` passes; `pnpm typecheck` fails in the page (`src/App.tsx`, `src/state/job.ts`, `src/components/StatusBar.tsx`, `src/components/TitleBar.tsx`, `src/bridge.fake.ts`: 18 errors, all from the example screen and its stand-in using the old bridge and the old command ids); `pnpm qa:audit` stops at its first state ("the audit itself failed: waiting for `.toast`"), because the example's states press shortcuts that `shortcuts.json` no longer has, so no gate after it runs. (With the window at Song2Vid's size and the old shortcuts, it fails 122 times: the title bar's overflow at 200% zoom and the note journey.) S2V-030 replaces those files. The gates passed on the renamed starter at the commit before the seam files and the window size changed; that commit is named in the ticket's comment.

## Hard for an outside developer

1. **The window size breaks step 3's promise.** README step 1 has you edit `app.config.json` (including the window), and step 3 says all five gates pass on the untouched starter. At Song2Vid's 560 x 760 window with a 480 x 640 minimum, the starter's own `qa:audit` fails 122 times: the example's title bar overflows at 200% zoom ("Use the light theme" spans 281 to 309 of 280), and its note journey fails because its two-pane layout is the narrow one. Run the gates once with the starter's window size, then change it; the first failure otherwise looks like a break you caused.
2. **"Marked blocks" are not marked.** The README, `electron/menu.ts` and others say "replace the marked blocks", but no file carries a marker line. `qa/audit.ts` has section dividers (`states`, `journeys`, `shortcuts`) and comments saying "replace", which is enough to find them with the README open, and not enough to prove, from the file alone, that a line outside them is unchanged. The list at the top of this file is the working definition.
3. **Replacing the contract is a rewrite, not a rename.** README step 5 says to replace "the contract names in `electron/tool/contract.ts`". For a tool that already has a contract (here `--json` lines, not `--events 1`) the capabilities call, the hello event, the sequence-number check, the stage names and the job request are all hard-wired in `adapter.ts`, `progress.ts`, `status.ts`, `jobs.ts`, the stand-in tool and every scenario file (each hard-codes `"tool": "example-tool"`). The tool-contract reference says an existing tool keeps its form; the starter has no path for that case. Song2Vid plans the rewrite as one ticket (S2V-029).
4. **Writing the bridge breaks the build on purpose.** The starter says to write `src/bridge.ts` "before any builder starts", but the preload, the main process, the stand-in bridge and the example page all implement or call it, so the type check fails from that moment until the builders arrive. The starter says nothing about the state in between. Song2Vid keeps `pnpm test` and `pnpm shell:check` green by updating the preload and menu in the same commit, and records the rest as red.
5. **A project's own `.gitignore` can hide starter files.** `build/icon.svg` is the file README step 1 names, and a root `.gitignore` with the common `build/` line drops it without a message. The starter's `.gitignore` does not un-ignore it.
6. **Public-repo scanners trip on starter files.** This repository's safety scan reported 663 problems in the untouched copy: `name@1.2.3` pins in `pnpm-lock.yaml`, the `@scope/pkg@version` entries in `pnpm-workspace.yaml` and `package.json`, and the loopback address `127.0.0.1` in the dev server, the audit server and two comments. The scan now needs a letters-only top-level part for an address and passes the loopback address (`scripts/safety-scan.sh`, a repository file, not a starter file).
7. **`command-palette` and `toggle-theme` are not in the SPEC's command list but the starter needs them.** The title bar reads `SHORTCUTS['command-palette']` and `['show-items']`, and the audit's shortcut gate checks that the theme button's tooltip shows its shortcut. A developer cannot tell which ids the starter's page and audit require and which are the example's. Song2Vid keeps `command-palette` and `toggle-theme`; `show-items` goes with the example's list rail.
8. **The test count drifts.** README says 64 tests pass (and 42, 49 and 29 elsewhere); the untouched starter ran 63 here on the Mac and on Titan. No test was skipped. The numbers read as a promise a developer will try to match.
9. **`pnpm` versions.** The starter pins `packageManager` `pnpm@11.9.0`. With pnpm 12 installed, `pnpm install --frozen-lockfile` quietly ran 11.9.0 instead. That worked, and the README's `npx pnpm@11.9.0` advice for a machine without pnpm does not say a newer pnpm switches by itself.
10. **The stand-in tool's name is hard-coded.** `test/helpers.ts`, `test/units.test.ts` and every scenario say `example-tool`, so changing `tool.name` in `app.config.json` does not fail any gate, and the gates do not prove the rename reached the adapter. S2V-029 rewrites them.
11. **The banned-terms gate and the notices.** The starter's gate bans words "in any text a person can read, Details and About included", and the skill's packaging rules require About to show third-party notices. For a product whose notices name the program that does the work (Song2Vid's FFmpeg notice, SPEC 26.2 and 27.8) the two collide. The gate has no exemption for notices text; S2V-030 must add one and record it.
12. **The bridge has no way to say which file a drop is for.** The README's bridge rule says a dropped file's location is resolved in the preload, but not what a page-owned Replace dialog (SPEC 4a) does with ids it does not keep. `releaseFiles` in `src/bridge.ts` is Song2Vid's answer.
